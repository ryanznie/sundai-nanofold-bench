Submission Guide

Zip Structure

Upload a .zip containing these files at the root level:

  • submission.py — your model entry point
  • config.yaml — training and data configuration
  • checkpoints/ckpt_last.pt — your trained checkpoint

Multiple step checkpoints are also accepted as checkpoints/ckpt_step_<N>.pt. The evaluator will use the highest-step checkpoint for scoring. Each checkpoint file must be under 500 MB.

Evaluation Pipeline

  • Predict: The service runs predict.py with your config against the official val set (100 proteins). Predictions are saved as pred_atom14 arrays in npz format.
  • Score: score.py evaluates each prediction against ground-truth labels and computes GDT-HA, lDDT-atom14, MolProbity Clash, and the composite FoldScore.
  • Leaderboard: Your best FoldScore (AUC over training samples) is used for ranking. The detail panel shows all component scores.

Scoring Metric

Rankings use FoldScore, a weighted composite:

  • 0.5 × GDT-HA — global fold accuracy (CASP standard)
  • 0.3 × lDDT-atom14 — local all-atom distance accuracy
  • 0.2 × MolProbity Clash — physical validity (no steric clashes)

All components are in [0, 1]; higher is better. See the Metrics page for full definitions.

Environment

  • Runs on GPU (CUDA). Ensure your code does not hard-code CPU-only paths.
  • Network access is not available during evaluation — all weights must be in the zip.
  • The evaluation host has the nanoFold-Competition repo available at /root/nanoFold-Competition. Your config.yaml may reference it for shared utilities.
Tip: Test your zip locally by running predict.py with your config before uploading. A submission that fails predict will show as failed with no score.
